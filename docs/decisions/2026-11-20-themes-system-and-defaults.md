# themes-and-cosmetics: the look as CSS, System, and the defaults

Date: 2026-11-20. Task: `themes-and-cosmetics` (survey-3 task 47, owner decision D4).

## The problem
The owner wants many more themes and cosmetic options, with defaults that suit anyone and the power-user looks as options. The app had 8 dark themes, one hard-coded look (monospace, macOS-style dots, glyph icons), and a theme switch re-rendered the whole app.

## Chosen
- **Every cosmetic setting is CSS on `<html>`.** `look.ts`'s `lookAttrs` turns the look into data attributes (`data-icons`, `data-tabs`, `data-controls`…) and custom properties (`--font-ui`, `--fs-k`, `--accent`…); `useLook` applies them in one effect. File rows get no new props, only static attributes (`data-ft`, the icon type; `data-git`; a `--tag-c` style), so a theme or look change re-renders no row (`FilePane.dom.test.tsx` counts). Text sizes are `calc(Npx * var(--fs-k))` and radii `calc(Npx * var(--rk))`, so one property scales them all. The file list measures its row height again after a look change (`LOOK_APPLIED`).
- **Themes stay CSS blocks** in `themes.css`; `themes.ts` lists their ids, names, schemes and groups. 39 in all: the original 8 unchanged, 12 light, 16 more dark (the well-known editor and terminal palettes), a high contrast pair and 3 retro ones. `themes.test.ts` checks every theme against WCAG AA: the original 8 for body text (fg-0 and fg-1 on their backgrounds), the new ones also for secondary text, muted text and icons (3:1), the accent and text on it, and the status colors. The high contrast pair meets AAA. A new token, `--on-accent`, is the text color on an accent fill.
- **System** (`theme: "system"`) shows `lightTheme` or `darkTheme` from `prefers-color-scheme`, live; with `prefers-contrast: more` it shows the high contrast pair. `data-theme` always holds the theme shown, never "system", so everything reading it (the terminal, the site's checks) keeps working.
- **The window's own theme** (what GTK or Windows draws, and what the webview reports as `prefers-color-scheme`) follows: a fixed theme sets its scheme; System hands it back to the OS. On Windows `setTheme(null)` follows the OS. On Linux tao 0.37 applies the desktop portal's color-scheme when the window opens and on each change, so System needs nothing until a fixed theme was set; then `setTheme(null)` (which clears GTK's dark preference) and `theme()` (which asks the portal) put the OS's back. No Rust change.
- **Defaults for new users:** System with the glasshouse light and dark pair (plain neutrals, a blue accent), the system UI font, window buttons in the platform's style (Windows: flat buttons on the right; Linux: GNOME's round ones), browser-style tabs, colored file-type icons, no stripes, effects off, motion following `prefers-reduced-motion`.
- **Existing users see no change.** Settings saved before (no `lookVersion`) keep their theme, font, density and scanlines and get the classic look (`LOOK_CLASSIC`) for everything new; the old density's text size becomes `fontSize`. The demo starts this way too, so the site's images still match. Version 2 settings are checked field by field (`sanitizeLook`).
- **Presets** (standard, terminal, compact, high contrast, retro) reset the look and set their own values; the theme, System's picks and the accent stay unless the preset sets them. "terminal" is the classic look.
- **Fonts:** the system UI font is the new default. JetBrains Mono (Nerd Font), JetBrains Mono, IBM Plex Mono and Fira Code are bundled; Iosevka and Berkeley Mono aren't, so Preferences offers them only when installed (a canvas measurement) and labels them "not installed" otherwise. Any installed family can be typed in (quotes and CSS syntax refused). The Nerd Font is always last in each list, for the sidebar's and the Nerd Font icon set's glyphs.
- **Windows High Contrast** (`forced-colors: active`): selection, active tabs and toggles use the system's Highlight colors; icons, dots and window buttons get `forced-color-adjust: none` with system colors. WebKitGTK doesn't support `forced-colors`; Linux's high contrast goes through `prefers-contrast` instead.
- **Fixed in passing:** the striped rows' `.row:nth-child(odd of .row)` (specificity 0,3,0) beat `.row.selected` and `.row:hover` (0,2,0), so a selected odd row showed the stripe, not the selection. The stripe rule is now `:where()`-wrapped.

## Rejected
- **Theme objects in TypeScript, set as inline properties.** The landing page and the demo use `themes.css` directly, and a CSS block per theme keeps the page's first paint right without JavaScript.
- **Switching the look through React props.** Every row would re-render on each change, which is what made big folders slow before (`PaneRow` is memoized for that).
- **Defaulting everyone to the new look.** An update shouldn't restyle an app someone set up; the classic look is one preset away for new users, and the new one for old users.
- **"system" in `data-theme`, resolved in CSS with `@media (prefers-color-scheme)`.** Every theme would need to be written twice, and custom themes couldn't be picks.
