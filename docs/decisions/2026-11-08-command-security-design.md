# Command security: who can call commands, and what reaches a shell

Date: 2026-11-08 · Task: `command-security` · Decided by the task session; the lead said to implement the plan in `docs/plans/completed/command-security.md` and list anything that could break a feature for review at merge.

## Threat model
glasshouse is meant to be a powerful file manager with a real terminal, so a page that can run script in the main webview already has the user's account: `pty_write` types into a shell, and `write_text` can rewrite `~/.bashrc`. Argument checks can't change that, so the design has two separate goals:
1. **Keep foreign code out of the webview and away from IPC:** an ACL, the CSP, and no devtools in release builds.
2. **Keep untrusted data from becoming commands.** Downloaded files, unzipped archives and cloned repos supply filenames, URLs, ssh hosts and `.git/config`, and those reach `cmd.exe`, PowerShell, tar, ssh and git. This needs no XSS at all, which makes it the more practical risk.

## 1. An app ACL, enforced at build time
**Before:** `build.rs` had no app manifest. tauri 2.10.3 (`Webview::on_message`) ACL-checks app commands only when an app manifest exists ("we only check ACL on plugin commands or if the app defined its ACL manifest"). So every page in any webview, remote origins included, could call all 71 commands.

**Now:**
- `src-tauri/permissions/app.toml` defines seven permissions, each a direct `commands.allow` list: `files-read`, `files-write`, `git`, `settings`, `launch`, `exec`, `window`.
- `capabilities/default.json` grants all seven to the `main` window. A capability with no `remote` entry applies only to the app's own (local) URLs, so a remote page loaded into the webview gets no command access.
- `build.rs` passes `AppManifest::new()` explicitly and **fails the build** when the commands in `generate_handler!` (src/lib.rs) and the commands in permissions/*.toml differ, in either direction. Tauri rejects an ungranted command at runtime, and most `api.ts` wrappers swallow the error through `safe()`, so a command another branch adds would otherwise just look broken. The error message says which file to edit.

Rejected:
- **`AppManifest::commands(&[…])`**, which generates `allow-<cmd>` and `deny-<cmd>` per command into `permissions/autogenerated/`. The capability would then list 71 entries, or a set of them, with the command list duplicated in build.rs on top. Hand-written groups say more about the attack surface.
- **Scopes on app commands** (`CommandScope`). Scopes are static capability data, but the allowed shells and hosts are only known at runtime, and a file manager needs every path.
- **Splitting the grants per window.** There is only one window. The groups make that a one-line change if a second, less trusted window (a pop-out preview, say) ever appears.

## 2. Argument checks on the commands that start programs
These are pure functions with unit tests, written to accept exactly what the frontend sends:
- **`pty_spawn` and `spawn_terminal_profile` → `check_profile`.**
  - A `shell` profile's exec must be one of the shells `detect_shells()` finds (the same probe `list_shell_profiles` uses), with no args.
  - `wsl` must be `-d <distro>`, where the distro uses only `[A-Za-z0-9._-]` and doesn't start with `-`.
  - `ssh` must be `<host>` or `-p <port> <host>`. The host can't start with `-`, so no `-oProxyCommand=`, and is limited to `[A-Za-z0-9._@:%[]/-]`.
  - Any other kind is refused.
- **`git_run` → `check_git_args` against `GIT_RUN_ALLOWED`:** one entry per subcommand the git menu sends, listing its allowed flags, its valued flags and how many plain arguments it takes.
  - The subcommand must come first, which rules out global `-c`, `-C` and `--exec-path`.
  - Any other argument starting with `-` is refused, so `fetch --upload-pack=…` and `rebase --exec …` can't get through.
  - A valued flag consumes the next argument as-is, as git's own parser does, so a commit message like "-fix" still works.
  - A new git menu item needs a line in this table; the refusal message names it.
- **`open_url`:** only `http`, `https` and `mailto`. Anything else would go to whatever protocol handler claims it (`ms-msdt:`, `search-ms:`, `file:`).

## 3. No user strings on a `cmd.exe` or PowerShell command line
cmd parses its own command line, and Rust's argument quoting follows MSVC rules, which cmd doesn't use. So `&`, `|` or `^` in a filename or URL ran commands. Each call site now avoids putting the string there at all:

| Command | Before | Now |
|---|---|---|
| `open_with_default`, `open_url` (Windows) | `cmd /C start "" <arg>` | `tauri_plugin_opener::open_path` / `open_url`, i.e. ShellExecuteExW via the `open` crate. As a side effect, URLs with `&` in the query string now open correctly. |
| `spawn_vscode`, `run_script` with `.bat`/`.cmd` | `cmd /C <script> <args>` | Spawn the batch file directly. std sends batch files through cmd.exe itself and escapes the arguments for cmd's parser (the CVE-2024-24576 fix). |
| `spawn_terminal`, pwsh/powershell fallback | `cmd /C start "" pwsh -WorkingDirectory <path>` | The folder goes in through the `GLASSHOUSE_CWD` environment variable, and the shell runs `Set-Location -LiteralPath $env:GLASSHOUSE_CWD`. Also fixes Windows PowerShell 5.1, which has no `-WorkingDirectory`. |
| `spawn_terminal_profile`, cmd fallback | `cmd /C start "" <exec> <args>` | Refused if any value contains a cmd metacharacter (`&|<>^%!"`). The profile check already rules them out for hosts and distro names. |
| `verify_signature`, `create_shortcut` | Path pasted into `-Command '…'`, with only ASCII `'` doubled | Paths go in through environment variables. PowerShell also treats ‘ ’ ‚ ‛ as single quotes, so a filename like `Tom’s.exe` could close the string. **Found during this task; it wasn't in the survey.** |
| `wt.exe -d <path>` and the profile args passed to wt | as-is | `wt_escape` puts `\` before every `;`. wt splits its command line into subcommands at any unescaped `;`, even inside an argument (`_commandDelimiterRegex` in AppCommandlineArgs.cpp), so a folder named `x;calc` ran calc. `Commandline::AddArg` turns `\;` back into `;`. |

## 4. tar and 7z: `--` before names
- `tar -czf <dest> -C <parent> -- <members>`, and the same for the `.tar.zst` pipe path. Without `--`, a member named `--checkpoint-action=exec=…` is a tar option that runs a command.
- 7z gets `--` too: it ends both switch and `@listfile` parsing. It was already safer in practice, since its paths are absolute.
- Checked with GNU tar 1.35 and 7-Zip 25.01; bsdtar handles `--` the same way.

## 5. Automatic git calls must not run repo-configured programs
**Found during this task; it wasn't in the survey.** `git_file_info` runs on every selection change. Reproduced in scratch:
- `git diff --numstat HEAD -- <file>` ran the repo's `core.fsmonitor` command and its `filter.<x>.clean` command.
- `git log -1 -- <file>` ran the repo's `gpg.program` when a commit carried a forged `gpgsig` header and the repo set `log.showSignature`.

So browsing into an unzipped or cloned repo and clicking a file ran its code.

Fix:
- The numstat now comes from libgit2 (`diff_tree_to_workdir_with_index` plus a literal pathspec). libgit2 has no fsmonitor support and never runs external filter drivers.
- The log call passes `--no-show-signature`.
- A unit test builds such a repo, first confirms the plain CLI fires all three, then checks that `git_file_info` fires none.

Not changed: commands the user starts from the git menu (`git_run`) keep git's normal trust model. Hooks on commit and LFS filters on add are expected there, the same as in a terminal.

## 6. Smaller limits
- **`run_script`:**
  - It's killed after 60 s.
  - stdout and stderr are drained on threads and capped at 1 MiB each, with the excess read and dropped so the script can't block.
  - Output is returned 2 s after exit even if a background child still holds the pipe; before, `Command::output()` waited for that child forever.
  - The result notes a timeout, truncation or an open pipe. Commands are still synchronous, so the UI waits up to that long; `async-commands` will change that.
- **`read_image_b64`:** a 64 MiB server-side ceiling, the frontend's largest request, matching `read_text`. Reading is capped at ceiling + 1 bytes, so a file that grows after the size check is still refused.

## 7. Devtools and CSP
- **devtools:** removed from the `tauri` features. Debug builds have the inspector anyway (`cfg(any(debug_assertions, feature = "devtools"))` in tauri). A `devtools` cargo feature (`pnpm tauri build --no-bundle --features devtools`) turns it on for debugging a release build.
- **CSP additions:**
  - `media-src 'self' data:`: the audio preview's `data:` URL was blocked, because media fell back to `default-src 'self'`.
  - `object-src 'none'` and `base-uri 'self'`, as cheap hardening; nothing uses `<object>`, `<embed>` or `<base>`.
- **Google Fonts stay allowed.** The default font, JetBrainsMono Nerd Font, is bundled, but the font picker's JetBrains Mono, IBM Plex Mono and Fira Code are loaded from Google by `index.html`. Removing the origins would quietly drop three picker options to fallbacks. The cost is one request to Google at every startup; bundling or lazy-loading those fonts is suggested as a follow-up. *Superseded by `2026-11-08-local-fonts-bundled.md`: the fonts are now bundled and the Google origins are gone.*
