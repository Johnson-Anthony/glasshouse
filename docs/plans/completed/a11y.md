## What was done
1. **File list** (`components.tsx`): a `grid` in the row modes (header row of `columnheader`s with `aria-sort`, rows of `gridcell`s, `aria-rowcount`/`aria-rowindex`) and a `listbox` of options in the card modes. The focus stays on the pane, which names the focused row with `aria-activedescendant` only while that row is in the page. Named "Files in <folder>", plus ", pane N" in split view. Column headers take the focus from the keys (Up from the first row; Left/Right/Home/End; Enter or Space sorts; Down or Escape goes back). A polite message says the folder listed and a re-sort (`announce.ts`). One row's selection change still re-renders two rows.
2. **Tabs:** each pane's bar holds a `tablist`; the label is the `tab` (roving `tabIndex`, Left/Right/Home/End), and the close control is a named `<button>` beside it. No e2e selector changed.
3. **Controls that weren't buttons:** the Inspector's edit/apply/cancel/make-writable/copy links and its quick-action chips, the permission cells (checkboxes while editing), the breadcrumb's segments and the tag chip, the terminal head's two controls, the status bar's terminal switch, the menubar's palette hint. The window buttons were already buttons; the middle one now says Restore when the window is maximized. Glyph-only buttons (toolbar, preview tools, Quick Look) have names in words; the sidebar and the Inspector are named landmarks.
4. **Keys:** Enter and Space on a focused button, tab, link or column header are that control's (`CONTROL_SELECTOR`). A mouse press on a tab or toolbar button leaves the focus in the file list. Ctrl+\\ also matches the physical backslash key, for layouts that type `\\` with AltGr.
5. **Dialogs:** `useDialogPanel` (`dialogs/dialogPanel.ts`) on every dialog, the palette included: role, `aria-modal`, name, focus in, Tab kept inside the topmost one, focus back on close. Alert, confirm and choice are `alertdialog`s described by their message. Toasts go to a `role="status"` region that's always in the page. The palette is a combobox over a listbox.
6. **Focus:** the active file pane has the focus when the window opens, and gets it back after a split or its closing rebuilds the panes.
7. **Contrast:** `--fg-2` and `--fg-3` reach 4.5:1 on `--bg-0`, `--bg-1` and `--bg-2` in all 39 themes, by lightness only; `--fg-4` (the old `--fg-3` in the original eight) is for what isn't read; the focus ring is checked at 3:1. Saved custom themes load, with `--fg-4` taken from their `--fg-3`; the theme editor's report uses the same checks. Forced colors covers what this task added; nothing new animates.
8. **Preferences:** the dialog uses the shared hook, its name is "preferences" (the gear isn't read), its close button is named, and the filter says when nothing matches.

## Follow-ups (not done here)
1. **Tab stops.** Tab and F6 move between the sidebar, the file lists and the terminal (the spec's Task #18), so the toolbar's buttons and breadcrumb, the tab bar, the Inspector's controls and the status bar aren't reachable with Tab. They're real, named controls now, reachable with a screen reader's own navigation, and tabs and column headers have their own keys. Making them Tab stops (or giving F6 more stops: toolbar, tab bar, Inspector, status bar) is the owner's choice.
2. **The sidebar as a tree.** Its rows are plain `div`s: no `tree`/`treeitem` roles, `aria-expanded`, `aria-level` or `aria-selected`, and no active descendant. Its group headers are buttons whose names include their glyphs ("▾ PINNED +"), with the + and ⋯ actions inside the header button. The tree's ⋯ menu rows are `div`s.
3. **Miller Columns.** The middle column is the file list (a grid); the parent and preview columns are plain `div`s with no roles or names.
4. **The terminal.** xterm.js's screen-reader mode isn't turned on, so its output isn't read.
5. **The menubar** holds the palette button inside `role="menubar"`, which isn't a valid child; menus weren't reviewed in this task.
6. **The two WebKitGTK differences** (above): draw the placeholder dashes with CSS instead of text, and say "folder" for a card-mode item some way WebKitGTK reads (an `aria-label` or `aria-description` on the option).
7. **Colored text** (error red, git letters) is held to 3:1, not 4.5:1; a danger menu item's red on the hover color isn't checked.
8. **The WebKitGTK tree check** could become a script in the repo and a CI step (ubuntu has Xvfb; it needs `gir1.2-webkit2-4.1`, `gir1.2-atspi-2.0` and `at-spi2-core`).
9. **The open and save dialog** (`chooser/`) uses the same file list and toolbar, so it has their roles; its own controls weren't reviewed.
10. **Site images:** `docs/media`'s hero images and tour clips show the old muted-text colors; `pnpm site:capture` re-records them.
